# Security review

**Review date:** 2026-07-29  
**Reviewed revision:** `ee4678bfb2fe17b58430ffb7a0138cb81dc88866` plus the hardening artifacts in this change  
**Decision:** NO-GO  
**Scope:** authorization, MFA, payment webhooks, uploads, audit immutability, secrets, incident
escalation, dependency risk, and public-route behavior

This is a repository-level security review, not an independent penetration test or a review of the
production AWS/Stripe configuration. “No critical authorization vulnerability found” means none
was identified in the reviewed code and tests; it is not a certification that none exists.

## Control assessment

| Area                             | Result                                    | Evidence and conclusion                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| -------------------------------- | ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Authorization coverage           | CONDITIONAL                               | `packages/auth/src/authorize.ts` is deny-oriented and relationship-aware. Role/API tests exist under `apps/web/tests/auth`, `apps/web/tests/*/api-authorization.test.ts`, and `apps/web/e2e`. A heuristic inventory found 112 route handlers; 107 reference a context/auth boundary and the remaining five appear public/integration-facing. This is useful coverage, not a route-by-route proof. No critical authz bypass was found, but SEC-01 and SEC-06 remain. |
| Admin MFA enforcement            | CONDITIONAL                               | `packages/auth/src/rbac.ts` marks administrator, finance, and super-administrator MFA required. Login rejects missing setup/verification, sessions retain verification time, and high-risk actions require fresh step-up. Tests: `apps/web/tests/auth/mfa.test.ts`, `login.test.ts`, `authorize.test.ts`. Production enrollment and an attempted admin login without MFA have not been evidenced.                                                                   |
| Webhook authenticity/idempotency | PASS (code)                               | `packages/domain/payments/stripe.ts` validates the raw signed body. `packages/domain/payments/services.ts` derives a deterministic audit ID from the Stripe event ID and claims it with conflict-safe insertion before applying the event. Payment E2E coverage is in `apps/web/e2e/payments-and-payouts.spec.ts`. A production Stripe replay drill is still required.                                                                                              |
| Child-adult communications       | PASS (code)                               | `authorize.ts` explicitly denies a private adult-child conversation and the communication service requires a monitored membership shape. Evidence: `apps/web/tests/communication/communication.service.test.ts` and `apps/web/e2e/communication-safety.spec.ts`. Safeguarding-policy and operational review remain human gates.                                                                                                                                     |
| Upload quarantine/scanning       | FAIL                                      | Project, assignment, communication, and content paths include magic-byte/size controls, private quarantine metadata, and deny downloads unless scan status is `clean`. Review found no configured scanner provider/worker that turns pending objects into a trusted result, and callback coverage is incomplete across upload families. Quarantine without scanning does not close the gate.                                                                        |
| Append-only audit                | PASS (database control); test defect open | Migration `packages/db/migrations/0001_audit_events_immutable.sql` installs separate UPDATE and DELETE blockers. On 2026-07-29 direct PostgreSQL attempts both failed with `audit_events is append-only`. Package tests reported 15 pass / 1 fail because Drizzle's outer error hid that inner phrase from the assertion; the database control itself denied the mutation. Fix the assertion before treating CI as green.                                           |
| Secrets handling                 | CONDITIONAL                               | `.env*` is ignored, example values are non-production, and `packages/config` validates core configuration. No production credential was identified in the reviewed files. Several runtime compositions access `process.env` directly, and no production Secrets Manager/Parameter Store policy, rotation record, least-privilege review, or secret-scanner result was provided.                                                                                     |
| Incident escalation              | FAIL                                      | Safety support tickets can create a critical incident and optionally call `SUPPORT_SAFETY_ESCALATION_WEBHOOK_URL`; abuse reports do not demonstrate the same escalation, and production delivery/acknowledgement is unproven. See [RUNBOOK_INCIDENT.md](./RUNBOOK_INCIDENT.md).                                                                                                                                                                                     |
| Production dependencies          | FAIL                                      | `pnpm audit --prod` on 2026-07-29 reported 0 critical, 3 high, 1 moderate across 477 dependencies: `sharp`/libvips GHSA-f88m-g3jw-g9cj and PostCSS GHSA-6g55-p6wh-862q, GHSA-r28c-9q8g-f849, and GHSA-qx2v-qp2m-jg93. Upgrade through normal dependency change control, then rerun the audit and image/file-processing tests.                                                                                                                                       |
| Public-route behavior            | PASS (code)                               | `proxy.ts` includes the public marketing allowlist, prevents locale rewrite recursion, and uses the production next-intl request configuration. Evidence: proxy unit coverage, 8 isolated E2E cases, and 40 desktop/mobile accessibility cases. Production deployment evidence remains a launch gate.                                                                                                                                                               |

## Findings

| ID     | Severity | Finding                                                                                                                                                                                                                                                        | Required remediation and closure evidence                                                                                                                                                             |
| ------ | -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SEC-01 | High     | State-changing application routes do not demonstrate CSRF-token enforcement. `packages/auth` has token helpers, but review did not find their use in app route handlers. SameSite=Lax cookies are defense in depth, not a replacement for explicit protection. | Enforce a verified token or a rigorously documented equivalent on every cookie-authenticated unsafe method. Add negative cross-site tests and a route inventory.                                      |
| SEC-02 | High     | Uploads can remain quarantined, but no real malware scanner integration and complete callback matrix were proven.                                                                                                                                              | Wire an authenticated scanner job/provider, keep pending/failed/error objects inaccessible, cover every upload family, test malicious/clean/error/replay cases, and alert on stale pending scans.     |
| SEC-03 | High     | Three known high-severity production dependency advisories remain.                                                                                                                                                                                             | Upgrade to dependency paths containing `sharp >=0.35.0` and `postcss >=8.5.18` (or later fixed versions), rebuild, scan the container, and attach a zero-high-or-approved-exception report.           |
| SEC-04 | High     | Incident escalation is optional and inconsistent between safety tickets and communication abuse reports.                                                                                                                                                       | Create one incident/escalation path, require monitored production configuration, preserve report linkage, and attach an end-to-end paging drill with acknowledgement.                                 |
| SEC-05 | Closed   | Locale routing and next-intl request configuration previously made public/core pages unavailable.                                                                                                                                                              | Closed in code with the Next 16 request proxy, public-route regression coverage, isolated E2E verification, and a 40-case accessibility run. Production load evidence remains tracked separately.     |
| SEC-06 | Medium   | Authorization evidence is broad but is not a complete method-by-method route matrix or independent adversarial test.                                                                                                                                           | Generate an inventory of every handler/method, actor, resource relationship, expected allow/deny, CSRF rule, and test. Obtain independent security review/pentest signoff before public launch.       |
| SEC-07 | Medium   | The append-only integration test asserts on a driver-hidden inner message and therefore fails despite the trigger blocking mutation.                                                                                                                           | Assert rejection by SQLSTATE/cause or re-read the unchanged row; run it against ephemeral PostgreSQL in CI.                                                                                           |
| SEC-08 | Medium   | Production secret storage, rotation, scanning, and access evidence are absent.                                                                                                                                                                                 | Store secrets in the approved manager, restrict IAM, rotate deployment/webhook/session secrets, enable repository/container secret scanning, and attach configuration evidence without secret values. |

No critical authorization vulnerability was identified during this review. The launch gate remains
**CONDITIONAL**, not PASS, until SEC-01/SEC-06 are closed and an accountable security reviewer signs
the route matrix and adversarial test results. SEC-02 through SEC-04 are independently sufficient
to keep the overall decision at **NO-GO**.

founder/security signoff.
